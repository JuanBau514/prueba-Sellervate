- Keep the README bilingual; record the model decisions, actual results and remaining requirements. Use Git only in the terminal; prepare a browser comparison link for the PR.

## Decisions

- V1 assigns one role per person, consistent across their memberships. Membership existence remains the brand access boundary; a global lead role never grants access to every brand.
- A generated `specialist_role` constant supports a composite foreign key from a reply to a specialist membership. It rejects both nonmembers and leads, and protects existing replies against later membership edits without triggers or security-definer functions.
- `external_id` is required and identifies a reply, not a whole ticket. The same external identifier can occur in another brand or source. Unknown measured response time is NULL, distinct from zero.
- Referenced identities, brands and assignments cannot be deleted. V1 has no offboarding UI; archival and historical memberships must be designed before that workflow is added.
- The user explicitly selected P1 next; P9a remains pending despite appearing earlier in the initial suggested order.
